## خلاصه اجرایی (فارسی)

این پروژه یک **فروشگاه اینترنتی چندفروشندگی (Multi-Vendor) ایرانی و بسیار بزرگ** ساخته‌شده با **Laravel ^13.0 و PHP ^8.3** است. زبان اصلی سیستم فارسی/RTL است و تقویم شمسی (Jalali) در سراسر سیستم استفاده می‌شود.

**قابلیت‌های اصلی:**
- سه پنل مجزا: مدیریت (admin)، فروشنده (seller)، کاربر (user) + API موبایل (Sanctum)
- سیستم چندفروشندگی کامل: ثبت‌نام ۴ مرحله‌ای فروشنده، احراز اسناد، قرارداد الکترونیک، تنوع قیمت فروشندگان (Price rows با seller_id)، محاسبه کمیسیون دسته‌ای، کیف پول فروشنده و تسویه حساب
- سیستم قیمت‌گذاری پیشرفته: هر محصول چندین `Price` (variant) با ویژگی‌های رنگ/گارانتی، رزرو موجودی، گرد کردن قیمت، چندارزی (Currency)
- ۱۱ درگاه پرداخت ایرانی (Zarinpal، به‌پرداخت ملت، سامان، سپهر، ای‌دی‌پی، سداد، زibal، ...) از طریق پکیج inline شده shetabit/multipay
- فروشگاه ماژول/پکیج متصل به `https://update.weblak.ir` (خرید، لایسنس، نصب خودکار ماژول در `Modules/`)
- سیستم تم (Theme) مستقل: فروشگاه در `themes/WeblakShop` با کنترلر، روت، ویو و ترجمه خودش
- نصب‌کننده وب (Web Installer) + خودبه‌روزرسانی‌کننده (Self-Updater)
- پیامک با ۵ سرویس‌دهنده (ای‌پی‌پنل، کاوه‌نگار، ملی‌پیامک، ایده‌پردازان، فراز)، WebPush، ایمیل
- CMS کامل: وبلاگ، صفحه‌ساز، فرم‌ساز، ویجت‌ساز صفحه اصلی/وبلاگ، منو، اسلایدر، بنر، نظرات، پرسش‌وپاسخ، دیدگاه‌ها، داستان (Stories وابسته به ماژول)
- انبارداری با حرکت موجودی (StockMovement)، مدیریت مرجوعی (RMA) کامل، تخفیف کد، سیستم معرفی (Referral)

## 3. High-Level Architecture

```
                    ┌─────────────────────────────────────────────┐
                    │              bootstrap/helpers.php           │
                    │   option() DB-settings, theme_asset(), ...   │
                    └─────────────────────────────────────────────┘
Request → ForceHttps → Language → [RedirectMiddleware global] → session stack
        → CheckBlockedDevice → Viewer (visit log) → RecordAdminSession
        → ROUTES:
             ├─ themes/WeblakShop routes (front.* / seller.* / user.*)  ← loaded FIRST
             ├─ routes/web.php (admin.*)        ← loaded again per locale (/fa /en)
             ├─ routes/auth.php (Breeze-ish auth)
             └─ routes/api/v1.php (mobile API, x-api-key + sanctum)

Panels:
  ├─ STOREFRONT (theme): home widgets, products, cart, checkout, blog, pages,
  │    user account (orders/wallet/tickets/returns/addresses), seller public pages
  ├─ SELLER PANEL (theme, prefix /seller): products/variants, orders, wallet,
  │    carriers/tariffs, tickets, notifications, statistics
  ├─ ADMIN PANEL (app/Http/Controllers/Back + resources/views/back, Vuexy RTL):
  │    URL = admin/{ADMIN_ROUTE_PREFIX} (secret env segment!)
  └─ API V1: auth, catalog, cart, orders, favorites, user, settings
       + public price-feeds: /api/v1/torob/products, /api/v1/emalls/products

Runtime-added systems:
  ├─ Theme system: AppServiceProvider::loadTheme() registers Themes\{Name}\src\ThemeServiceProvider
  ├─ Module system: Modules/{Name} via nwidart + custom spl_autoload in bootstrap/app.php
  ├─ Packages marketplace: PackageApiService ⇄ https://update.weblak.ir
  └─ Installer: /install wizard (rachidlaasri) gated by storage/installed marker
```

**Key architectural decisions:**
1. **Theme owns the storefront**: controllers, routes, views, translations (`front::` namespace), even the whole seller panel live inside `themes/WeblakShop`. Root app = admin panel + API + core models/services.
2. **Settings are DB rows**, not config: the `options` table + `option($name)` helper (cached forever per locale). Admin UI writes options; several settings also rewrite `.env` via `change_env()`.
3. **Everything is audited**: `GlobalActivityObserver` auto-attached to ~all models writes spatie activity_log rows.
4. **Pricing lives in `prices` table** (multi-vendor offers per attribute-combination), NOT on products.
5. **Multi-currency**: prices stored as `decimal(64,8)` in row currency; converted to **integer Toman** at runtime via `products.currency_id` → `currencies.amount`.

## 5. Request Lifecycle & Route Loading (CRITICAL)

1. **Global middleware**: PreventRequestsDuringMaintenance → ValidatePostSize → TrimStrings → ConvertEmptyStringsToNull → **RedirectMiddleware** (DB `redirects` table 301/302 manager; fails silent if DB not ready).
2. **`web` group**: **ForceHttps** (non-localhost always → https!) → **Language** (locale from 1st URL segment) → cookies/session/CSRF → **CheckBlockedDevice** (admin device fingerprint blocklist) → **Viewer** (logs EVERY GET request to `viewers` table with device data via jenssegers/agent) → **RecordAdminSession** (admin device sessions).
3. **Route loading order**: `AppServiceProvider::boot()` runs BEFORE `RouteServiceProvider`, so **theme routes (storefront) are registered first** — this is why the theme's `POST /login` (mobile/OTP flow) overrides `routes/auth.php`'s Breeze login.
4. **routes/web.php is loaded 3×** — once bare, once per locale prefix (`/fa`, `/en` with name prefix `{locale}.`). A custom `route()` helper in `bootstrap/functions.php` resolves locale-prefixed route names. ⚠️ Never assume a route exists once.
5. **Admin URL is dynamic**: `admin/{ADMIN_ROUTE_PREFIX}` (env `ADMIN_ROUTE_PREFIX` — secret; **NOT in .env.example**).
6. **`api` group**: Sanctum stateful → throttle:api (60/min) → bindings → **EnsureApiHeaderIsSet** (requires `x-api-key` header matching an active row in `apikeys` table; exempts torob/emalls feeds).
7. **Installer gate**: if `storage/installed` missing → AppServiceProvider redirects everything to `/install`; `MyEnvironmentManager` writes a fixed `.env` (CURRENT_THEME=WeblakShop, file cache/session, sync queue, predis). `application_installed()` helper checks the marker file.
8. **Sitemap/robots are static files** (`public/sitemap/`, `public/robots.txt`) regenerated on demand — web server serves them before Laravel.

## 6. Database — Conventions & Domains

### 6.1 Global conventions
- **All money = integer Toman** (bigint); `prices.price` is `decimal(64,8)` only for foreign-currency products (converted via `Currency.amount`).
- **Row-level multilingual**: `lang` column (default `fa`) on ~24 content tables + `Languageable` trait (`scopeDetectLang`).
- **Soft deletes** only on: prices, discounts, warehouses, carriers, currencies, attribute_groups, attributes, size_types, provinces, cities.
- Morph map rewritten to `App\Models\...`; `notifications.type` stores short class names.
- Heavy explicit indexing; `option()`/`options` table = settings store; `user_options` = per-admin UI prefs.
- **Commission/discount = integer percent**; snapshots copied onto orders/order_items at payment time.

### 6.4 Seeders (DatabaseSeeder order)
ProvinceSeeder (31 provinces) → CitySeeder → PermissionSeeder (from `config('general.permissions')` tree, prunes stale) → RoleSeeder («مدیر کل» = ALL permissions) → MenuSeeder → CategorySeeder → SliderSeeder/BannerSeeder (theme-config driven, copies demo images) → ProductSeeder (5 products) → AttributeSeeder (colors + گارانتی) → StaticFilterSeeder → LinkSeeder → WarehouseSeeder (انبار مرکزی) → ReturnReasonSeeder (6 Persian reasons + options return_days_limit=7, return_enabled=1).
**No admin seeder** — first admin created by `/install` (level `creator`).

### 6.5 Price & commission math (the most important business rules)
- Final price = `regular_price` rounded per `products.rounding_type/amount` (close/up/down × 100/1000/10000/100000 from product or `option()` defaults) → cached into `prices.regular_price`; discount % → `prices.discount_price` cache.
- Cart totals computed LIVE in `Cart` model (never stored): sums pivot `Price::salePrice()`.
- **Commission**: on payment, `Order::priceSellerDepositWallet(sellerId)` resolves `Category.commission` by **walking up the category tree** (first non-null wins), writes percent onto each `order_item.commission`, computes `priceForSeller = price×(100−Σcommission)/100`, `priceForSite` = rest → writes `seller_deposits` row (site cut) + deposit into seller wallet.
- Order items snapshot: `price` = unit after discount, `real_price` = unit before (backfill formula `price×100/(100−discount)`).
- Stock: `Price.reserveStock/decrementStock/incrementStock/unreserveStock` (DB::transaction + `stock_movements` rows). `prices.reserved_stock` holds pending-order stock.

```
Payment: gateway callback → transactions(status=1) → Order.status=paid → OrderPaid event
Commission: order_items.commission% ← Category.commission (parent walk) → seller_deposits + seller wallet deposit
Return: ReturnRequest → order/orderItem/reason + ReturnImages; refund split by payment_type (cash/credit/installment)
Content: Product|Post|Page|Form ⇄ Tag; Comment morph (self-replies = Q&A); Like morph; Gallery/File/Label morphs
Placement: Slider/Banner JSON pages+groups+places; Widget → WidgetOption → Category pivot; Menu self-tree

```

**Model behaviors worth knowing:**
- `Product`: sluggable, routeKey=slug, `HasProductId` (code p-{jy}NNNN), `getPrices()` respects `option('multi_vendor_system_status')` + only fully-active sellers, `lowestPrice` via raw SQL ordering by COALESCE(discount_price, regular_price), `scopeFilter` (attributes/specs/brands/price/search/sort), `refreshRating()`, cacheKeys + observer cache clearing.

## 9. Cart → Order → Payment → Wallet (THE core flow)

1. **Cart**: guest carts keyed by `cart_id` cookie (Cart row user_id null). On `Login` event, listener `UserLogin\GetCart` merges guest cart into user cart (dedupe by product+price). Add-to-cart validates `Price::hasStock()`; download products only once.
2. **Coupon**: one code per cart (`carts.discount_id`); `Cart::canUseDiscount()` validates 11 rules (date window, whitelist, first purchase, global/per-user quantity, least price, least items count, include/exclude products/categories, ceiling...). Snapshots copied to order at creation.
3. **Checkout** (theme `OrderController@store`, 1700+ lines):
   - Splits cart into **physical vs download**; download-only skips address/shipping.
   - Groups physical items **per seller** (`seller_{id}` groups + `store` group for shop's own items) — each group gets its own carrier + delivery date + shipping cost.
   - Shipping cost: `calculateCarrierCost` → carrier active? → carrige_forward? → free-shipping weight/price → `Tariff` by within/extra-province & max_weight → `extra_cost` per kg overage. Delivery dates use `HolidayService` (Fridays + Jalali holiday JSONs 1405–1410).
   - Creates `Order` (unpaid; price = items + shipping − discount) + `OrderItem`s (price/real_price/discount/attributes JSON/commission later/shipping per item) — `orders.seller_id` = JSON array of seller ids.
   - **InstallmentPayment module** (if active): `InstallmentService.analyzeCart` splits credit-eligible items, rewrites order price. **CreditPay module**: creates CreditOrder + CreditInstallments, price = cashPaid + firstInstallment + shipping.
   - Dispatches **`CancelOrder`** job delayed `option('order_cancel',1)` hours (auto-cancel unpaid: unreserve + restock + ProductPricesChanged).
   - Fires **`OrderCreated`** → listeners `SaveAddress` (persist address) + `ChangePrices` (PriceChange snapshot + **stock decrement**).
4. **Payment** (`pay()`): reserve stock per item (`StockMovementService`, idempotent) → zero-price → `orderPaid()` directly → `wallet` → `payUsingWallet` (insufficient balance: create fail history, charge wallet via gateway first, continue) → else **shetabit**: `Payment::via($gateway)->config(get_gateway_configs($gateway))->callbackUrl(route('front.orders.verify', gateway))->purchase(Invoice, fn→ insert transactions row (morph Order, transID, gateway_id) + session)->pay()->render()`.
5. **Verify** (`front.orders.verify` any-method callback): find pending transaction by session transID → driver verify → transaction status=1 + traceNumber → **`orderPaid($order)`** (DB::transaction): re-check stock with `lockForUpdate` (stock − reserved ≥ qty), `confirmReservation()` (unreserve + out movement + sold_count++), stock_before/after on items, status=paid + paid_at → fire **`OrderPaid`** (product sell counters++, admin DB notifications, optional SMS user/admin/seller per options). Failure → `cancelOrderAndRefund()` (release reservations + wallet refund + order canceled + OrderCancelled notification database+WebPush).
6. **Wallet**: charge via `front.wallet` + callback `front.wallet.verify`; withdraw request = WalletHistory(withdraw=1) → admin `RequestDepositAdmin` approval (`WalletController@status_pay`: waiting/pay/unpay/**unpay-refund** — refund creates compensating deposit + trackingId). Seller payouts use the same rows. `WalletAmountIncreased/Decreased` events → SMS listeners (option-gated).

### Scheduler (Console/Kernel; needs cron `php artisan schedule:run`)

- everyMinute (withoutOverlapping): `queue:work --daemon --tries=3 --sleep=3 --queue=default`

- daily 22:00 `clear:tmp` · daily 00:00 `sitemap:generate` + `CalculateViewers` · daily 01:00 `HappyBirthday`

### Custom artisan commands
`application:install`, `shop:link` (merges filesystems.links + theme links → symlinks), `theme:config`, `updater:update`, **`updater:after`** (optimize:clear → migrate → seed PermissionSeeder → app:fix → shop:link → queue:restart → optimize → theme:config), `app:fix`, `sitemap:generate` (spatie), `clear:tmp`, `torob:update`, `dump-autoload` (shared-hosting wrapper), `clean:import-logs`, `get:article_ai`, `product:generate-old-ids`, `packages:verify-licenses {--notify}`.

## 27. ⚠️ KNOWN BUGS / DEAD CODE / GOTCHAS (READ BEFORE CODING)

1. **`prices.seller_id` id-space inconsistency**: `ProductSellerController::variant_store` writes `seller_info()->id` (**SellerInfo id**) while order flow does `Seller::find($price->seller_id)` — two different id spaces for the same column. Verify before touching seller pricing.
2. **`orders.seller_id` is a JSON array** of seller ids, not a scalar; some code treats it as single relation (`$order->seller`) — seller SMS/notifications only fire when it happens to resolve.
3. **Broken route** `front.get-stores-cached`: closure calls `App\Http\Controllers\Front\ProductController` which **does not exist** → 500 if hit.
4. **Story features are module-dependent**: theme references `Modules\Story\...` models/trait and routes `front.setStorySeen`/`front.setStoryInteraction` that don't exist without the Story module; the `main-story` widget renders nothing without it. Seeded story widget may error.

6. **Broadcast channels public**: `orders`/`contacts` authorization returns true for everyone.
7. **`front.products-widgets` config referenced** by WidgetTemplateRegistry but doesn't exist (products-page widgets unsupported).
8. **Theme asset symlink**: `public/themes/WeblakShop` is empty in git — must be created at deploy (`shop:link` / theme activation), else all theme CSS/JS 404.
9. **HTTPS forced** (ForceHttps + session same_site=none + secure=true) — local HTTP breaks unless localhost.
10. **API needs `x-api-key`** header (apikeys table) — Postman tests fail without it (except torob/emalls).
11. **`option()` caches forever** — direct DB edits to `options` are invisible until cache clear; `option_update()` clears properly.

13. **Three updater systems coexist**; only DeveloperController+ProcessUpdateJob (vs update.weblak.ir) is real; `updater:after` is mandatory post-update.

16. **GlobalActivityObserver attaches to ~all models** — schema churn writes activity rows; exclusion lists matter for performance.

## 28. Development Conventions for Future Agents (Do / Don't)

**DO:**
- Put settings in `options` via `option()/option_update()`; add admin UI in `Back\SettingController` if needed.
- Route all stock changes through `Price::reserveStock/decrementStock/incrementStock/unreserveStock` / `StockMovementService`.
- Use `uploadOptimizedImage()` for uploads (and extend its path switch for new models).
- Follow existing patterns: `apiIndex` + `datatable()` helper for admin datatables; `authorizeResource` + `config('general.permissions')` entries for new admin sections; activity logging comes free via GlobalActivityObserver.
- Put storefront/user/seller features in the **theme** (`themes/WeblakShop`), admin features in `Back` controllers + `resources/views/back`.
- Respect the money format: integer Toman; discounts integer percent; snapshots on order rows.
- Use Jalali helpers (`jdate`, `Jalalian`, `convertPersianToEnglish`) and `local_info()` for RTL/LTR.
- When adding an admin URL use `route('admin....')` / `admin_route_prefix()` — never hardcode.
- For new marketplace-style features, follow `PackageInstallerService` patterns (signature verify, ModuleInstallLog, permissions seeding).
- Run `php artisan optimize:clear` after changing options/env/config caches; remember `.env` edits go through `change_env()`.

**DON'T:**
- Don't touch `packages/shetabit` or `packages/codedge` unless fixing the package itself (they shadow vendor/).
- Don't assume `Modules/` exists — it appears only after a package install.
- Don't write to `viewers`/`statistics` directly; use the middleware/job flow.
- Don't broadcast sensitive data on `orders`/`contacts` channels (they're public!).
- Don't edit `public/sitemap/*.xml` or `robots.txt` by hand — they're regenerated.
- Don't create Price rows without thinking about `attribute_hash` uniqueness (seller+attributes) and needing `get_attributes` loaded.
- Don't skip the `Seller` middleware checks when adding seller routes; respect `multi_vendor_system_status` option.
- Don't trust `$order->seller` as a single relation (it's a JSON array column; use `$order->sellers()` via order_items).
